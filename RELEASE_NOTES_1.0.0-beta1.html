First beta after 1.0.0-alpha1. The feature set for the 1.0 line is considered complete enough for wider testing: ten backends, smart routing, fact check, extensibility events, and admin-tunable prompts. Please report issues on the project issue queue.

Requirements: Drupal ^11.1 || ^12, PHP ^8.3, AI ^1.2, Key ^1.18.

composer require 'drupal/ai_provider_universal:^1.0@beta'
drush pm:enable ai_provider_universal
# optional:
drush pm:enable ai_provider_universal_router ai_provider_universal_factcheck

Development branch: composer require drupal/ai_provider_universal:1.0.x-dev.

What is this module?

A multi-instance AI provider for the Drupal AI module. Infrastructure is modeled as config entities:

  • Servers (ai_universal_server) — one endpoint each (backend, host/key, limits).
  • Models (ai_universal_model) — discovered per server, exportable, with operation types, routing metadata, sampling overrides, and optional catalog features.

Optional submodules: Smart Router (cost-aware virtual routes) and Fact Check (claim verification + content scan).

Highlights

  • Smart routing beyond cost. Routes can now require catalog features (tools, reasoning, json_mode — read live from the server), and every model carries sampling overrides (temperature, top_p, penalties). Duplicate a model entity with different sampling to tune the same model per use case — routing treats the variants as independent candidates.
  • Every prompt is yours. All eight tunable LLM prompts (six fact-check, classifier, route verifier) are editable from the admin UI, with sprintf-token validation and shipped defaults you can always fall back to. Translate them, add domain guidance, tighten them for your models.
  • Two new backends with real metadata. Local ollama (native /api/show enrichment: true context windows, capabilities, free-cost prefill) and groq (live pricing, context and feature flags from the catalog).
  • Built to be extended. New ModelPostCallEvent and ModelsDiscoveredEvent join the pre-call gate, and routed calls are tagged (smart_route:&lt;id&gt;, route_complexity:&lt;class&gt;) so the AI core's ai_observability logs attribute every call to its route.
  • Hardening pass. SSRF guard on standalone URL scans, per-role scan flood limits, and prompt-injection mitigations baked into the shipped fact-check prompts.

Changes since 1.0.0-alpha1

Backends

  • Ollama (ollama) — dedicated local backend; discovery enriches /v1/models via native POST /api/show (context length, family/capabilities); costs prefilled as free for smart routing.
  • Groq (groq) — fixed api.groq.com/openai/v1; live pricing, context, modalities, and supported_features from the catalog.
  • Clearer separation: use ollama for self-hosted daemons, ollama_cloud for ollama.com.
  • Discovery is more resilient: per-model enrichment failures log and fall back instead of aborting the whole run.
  • Ollama models proxied to ollama.com (ids ending in -cloud) are not marked free — they are metered on ollama.com, so their costs stay unset for you to fill in.

Models & discovery

  • Catalog features (supported_features) persisted on models when the backend publishes them; always refreshed on re-discovery.
  • Sampling overrides per model (temperature, top_p, frequency_penalty, presence_penalty) on every chat call; vendor recommendations prefilled from definitions/model_defaults.yml when known.
  • Quality tier prefill: family/size heuristics plus a price-band fallback for live-pricing catalogs (so large catalogs are not left unrated).
  • Manual cost / tier / context / reasoning / sampling edits are still never clobbered by re-discovery.

Smart Router

  • Verifier model on a route — lightweight yes/no check before return; one retry with the best remaining candidate on rejection.
  • Complexity classifier — optional local model for prompts heuristics treat as simple; admin setting + fallback to heuristics.
  • Required catalog features on routes (e.g. tools, reasoning) — candidates must report them.
  • Admin-editable routing prompts (classifier system prompt, route verifier) with sprintf token validation.
  • Decision log now exposed as editable Views (decisions list with sortable columns + JSON/REST export); savings dashboard moved to Reports.
  • New Smart routing settings page (classifier model — previously config-only — and routing prompt overrides).
  • Routed calls tagged smart_route:&lt;id&gt; / route_complexity:&lt;class&gt; for ai_observability attribution.

Fact check

  • Admin notifications — AdminNotifier + FactcheckNotificationEvent (always dispatched; optional default email via notify_email; ECA/subscribers can suppress mail).
  • Content-scan flood limits per role/session.
  • Prompt overrides for the six fact-check LLM templates (empty = shipped default).
  • Media Bias Fact Check bias import (static JSON + optional RapidAPI drush factcheck:sync-bias-ratings).
  • Fact check results content entity + Views history; standalone page/block improvements.
  • Standalone URL fetch SSRF protection (public http(s) only; private/reserved addresses blocked).
  • Prompt-injection mitigations in the shipped templates: scanned text, claims and evidence are explicitly framed as data, never instructions.
  • Trusted-site seeds expanded: scientific sources (PubMed, Nature, Science, arXiv — the latter flagged as not peer-reviewed) and wire services (Reuters, AP) join WHO/UN/Wikipedia. All created unpublished: reputation stays an editorial decision.
  • Settings UX: key_select + refresh; breadcrumb-friendly path under AI config.
  • Batch claim verification robustness and extractor language pinning.

Extensibility events

  • ModelPreCallEvent — block or swap model before every call (pre-call gate).
  • ModelPostCallEvent — tokens + latency after successful chat.
  • ModelsDiscoveredEvent — adjust discovered models before persistence.
  • UsageThresholdEvent (router) — alert / exhausted daily limits.
  • FactcheckNotificationEvent — admin alerts for scans and settings changes.

Platform & DX

  • Core requirement tightened to Drupal ^11.1 || ^12 (PHP ^8.3).
  • OOP hooks where needed; Spanish interface strings expanded for main, router, and factcheck.
  • PHPUnit attributes; Kernel tests use RunTestsInSeparateProcesses.
  • Documentation refresh: README, glossary, servers-and-models, smart-routing, factcheck, usage-limits, adding-a-backend.

Recommended AI core patches

Still recommended (shipped under patches/, declared in this module’s composer.json). Enable dependency patching with composer-patches:

  • Optgrouped model options in AI settings form.
  • ai_search embeddings engine parsing for model ids containing double underscores.
composer require cweagans/composer-patches
composer config extra.enable-patching true
composer update drupal/ai

Upgrade notes (from alpha1)

  • Config export/import: new model fields (supported_features, sampling), route fields (required_features, verifier), factcheck settings (notify, flood, prompts), router settings (classifier, prompts). Re-export site config after upgrade.
  • Routing decisions report moved: now under Reports at /admin/reports/ai-router-savings (was /admin/config/ai/providers/universal/routes/log) — update bookmarks. A quick-access button remains on the Smart Routes page.
  • Local Ollama: prefer backend ollama over generic openai_compatible for richer discovery metadata (re-save server / re-run discovery).
  • Drupal 10: no longer supported; use Drupal 11.1+ or 12.
  • No automated migration from ai_provider_llama_cpp — recreate servers under this module.

Submodules

  • ai_provider_universal_router — smart routes, usage-limit enforcement, decision log.
  • ai_provider_universal_factcheck — claim verification, content scan, trusted sites, notifications.

Full documentation lives in the package under docs/ and in the project README.

Known limitations (beta)

  • Inference is OpenAI-protocol only; native Anthropic/Gemini backends still need “inference dispatch through backends” (roadmap).
  • Token estimates for routing use chars/4, not a real tokenizer.
  • No time-of-day pricing schedules yet.
  • OpenRouter embedding catalog merge and several UX items remain on the roadmap.

Thank you for testing the beta. Feedback on real-world multi-provider fleets and smart-route savings numbers is especially welcome.
