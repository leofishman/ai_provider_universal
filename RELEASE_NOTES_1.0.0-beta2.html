AI Provider: Universal 1.0.0-beta2

Changes since 1.0.0-beta1.

Highlights

  • No AI core patches required. Model IDs use a dot separator (server.model, smart routes route.<id>) and getConfiguredModels() returns a flat model_id => label map. AI settings and ai_search resolve Universal models out of the box (fixes #3611069 — “Universal | Array” in the embeddings engine select).
  • Content governance submodule (ai_provider_universal_governance): default Guardrail set attach, AI-origin provenance events, disclosure suffix / origin marker / fact-check and AI-likelihood Guardrail plugins, field-based disclosure UI, and recipes (see below).
  • Scheduled content review (factcheck): scan profiles enqueue checks on node save; cron/queue runs them; optional content-review events for ECA/Workflow.

Recipes

Bundled under recipes/ in the project. Apply with core’s recipe runner (path relative to your Drupal root; adjust if the module lives elsewhere). Recommended one-shot for an Art. 50-style setup:

php core/scripts/drupal recipe modules/contrib/ai_provider_universal/recipes/ai_content_governance_starter

  • ai_content_governance_starter — applies disclosure, enables governance + factcheck, installs scan profile editorial_light (readability on published articles, event on threshold). Provenance emission and default Guardrail attach stay off until you configure them. Does not install ECA/Workflow.
  • ai_content_disclosure — disclosure fields only: field storages + Article fields for AI origin, disclosure-required flag, and human-asserted exemption (with audit). Requires the Article content type. The governance submodule can render <meta name="ai-origin"> and a visible label from these fields.
  • factcheck_trusted_sites — trusted site content type (domain + reputation −10…10) for curating web evidence in fact check.
  • factcheck_trusted_sites_seeds — optional example trusted-site nodes (created unpublished). Apply factcheck_trusted_sites first; set reputation and publish editorially.

Full design and ECA wiring notes: docs/content-governance.md. Fact-check trusted sites: docs/factcheck.md.

Upgrade notes (from beta1)

  1. Run database updates: drush updb (update 10102 renames model entity IDs from server__machine to server.machine and rewrites stored references in AI defaults, smart routes, router/factcheck settings, Search API embeddings engines, and usage counters).
  2. Clear caches: drush cr.
  3. If you previously applied the module’s recommended drupal/ai patches (optgroups / explode limit 2), you can remove them — they are no longer needed for this provider.
  4. Optional: enable ai_provider_universal_governance, or apply the ai_content_governance_starter recipe, then review Configuration → AI → Providers → Universal → Content governance.

Changes

  • Flat model options with Server: model labels (no nested optgroups).
  • Model ID separator . instead of __ so AI core’s provider__model parsing stays correct.
  • Content governance submodule + recipes ai_content_disclosure / ai_content_governance_starter.
  • Scan profiles for async content review (factcheck); starter profile via the governance recipe.
  • Docs: glossary, servers-and-models, smart routing, usage limits, content governance; README installation, config paths, and recipes.
  • Spanish translations updated (main, router, factcheck); new ai_provider_universal_governance.es.po.

Requirements

  • AI ^1.3 (Guardrails API for governance features)
