AI Provider: Universal 1.0.0-rc1

Changes since 1.0.0-beta4. Release candidate: no new features are planned before 1.0.0, only fixes.

Security hardening

A security pass over the whole module ahead of the security advisory coverage review. None of these was exploitable without an account holding the permission involved.

  • Fact check results: viewing no longer grants editing. view factcheck results was the entity's admin permission, so anyone allowed to view results could also create, edit and delete them wherever entity access is the gate (JSON:API, REST). Viewing now needs that permission; changing or deleting needs administer factcheck settings.
  • URL fetching is pinned and capped. PageFetcher, used by the standalone fact check and the terms API, connects to the address it checked, closing a DNS rebinding window between the check and the request; follows redirects by hand, checking and pinning each hop, five at most; and reads at most 5 MB, streamed, instead of loading any response whole into memory.
  • use standalone fact check is marked restrict access: the site fetches any public URL the user gives and spends API budget on it.
  • Plagiarism matches link only http(s) URLs: an empty or javascript: URL from the search API made the results page fail to render.
  • The Hugging Face pipeline tag lookup only takes org/name repo names; the name comes from the server's response and went into the URL path.

New: terms and privacy analyzer (experimental)

  • ai_provider_universal_terms reads terms of service or a privacy policy, pasted or by URL, and returns findings in 19 categories (arbitration, data sharing, auto-renewal, …), each quoting the clause it comes from. Every quote is checked against the text and invented ones are dropped, so the response can only hold known categories and text that really is in the document. Results are cached by the hash of the normalized text, never by who asked. Not legal advice, and every response says so.
  • API: POST /api/terms/analyze?_format=json with {"text"} or {"url"}, behind the use terms analyzer permission (restrict access). JSON bodies only; cookie sessions send X-CSRF-Token; at most requests_per_hour (default 30) per user, or per IP for anonymous callers, answering 429 above it.
  • Settings at /admin/config/ai/terms: model, piece size, longest document, requests per hour.
  • Measured on Spanish documents only (F1 0.89 with Qwen3.6-35B-A3B, reasoning off, temperature 0): the prompt and category descriptions are Spanish, and findings' descriptions come back in Spanish on any site. An English prompt measured on English documents is next. See docs/terms.md.

Other changes

  • Requires AI ^1.5 (was ^1.3): AI 1.3.x is out of support.
  • Docs: the content scan needs node view access, as the code has required since July (the docs and the permission description said update).

Upgrading

  1. composer update drupal/ai_provider_universal drupal/ai (AI 1.5 or newer).
  2. drush updb: sets the terms API's hourly limit on sites that already enabled the submodule from 1.0.x-dev.
  3. drush cr.
  4. Check roles that hold view factcheck results: they keep viewing results but can no longer change or delete them. Roles granted use standalone fact check keep it; the permission is now flagged as restrict access on the permissions page.
  5. Callers of the terms API from 1.0.x-dev: send Content-Type: application/json, and X-CSRF-Token when authenticated by cookie.

Known limitations

  • Jev (TypeSafe) and OpenAI's Decisions API (gpt-6-luna) are still not verified against their live APIs; everything decision-related is verified end to end against self-hosted Laya, and against both documented wire formats with mocked HTTP.
  • The Decision and terms submodules are experimental: Decision targets AI 1.6.x-dev, whose interfaces may still change, and terms is measured on Spanish documents only.
  • URL pinning needs Guzzle's curl handler (Drupal's default when the curl extension is loaded), and hosts without an IPv4 address are refused.

Requirements

  • Drupal 11.1+ / 12, PHP 8.3+
  • AI ^1.5 (the Decision submodule needs 1.6+)
  • Key

Install: composer require 'drupal/ai_provider_universal:^1.0@RC'
