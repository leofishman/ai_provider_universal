# Changelog

## 1.0.0-rc1 — unreleased

- **Requires AI ^1.5** (was ^1.3): AI 1.3.x is out of support. Fallbacks for AI 1.3/1.4 stay in the code but are no longer tested.
- **Security audit fixes** before the security advisory coverage review:
  - Fact check results: `view factcheck results` was the entity's admin permission, so anyone allowed to view results could also create, edit and delete them wherever entity access is the gate (JSON:API, REST). Viewing now needs that permission; changing or deleting needs `administer factcheck settings`. Roles holding only the view permission lose write access, as intended; no update hook, a cache rebuild is enough.
  - `use standalone fact check` is marked *restrict access*: the site fetches any public URL given and spends API budget on it.
  - Plagiarism matches link only http(s) URLs; an empty or `javascript:` URL from the search API made the results page fail to render.
  - The Hugging Face pipeline tag lookup only takes `org/name` repo names (the name comes from the server's response and went into the URL path).
  - `PageFetcher` reads at most 5 MB, streamed: refused up front when Content-Length says so, cut off while reading otherwise. A URL to a large file used to be loaded whole into memory.
  - `PageFetcher` connects to the address it checked (closing a DNS rebinding window between the check and the request) and follows redirects by hand, checking and pinning each hop, five at most. Without the curl extension the pin would be ignored, so URL fetches are refused instead.
  - `PageFetcher` refuses every non-global IPv4 range (`FILTER_FLAG_GLOBAL_RANGE`), plus an explicit deny list: 100.64.0.0/10 (shared address space: cloud metadata such as 100.100.100.200, CGNAT, Tailscale), 192.0.0.0/24, 198.18.0.0/15 and multicast 224.0.0.0/4, which the private/reserved flags let through.
- **No third-party ratings in the repository**: `data/mbfc-ratings-full.json` (~8,700 Media Bias/Fact Check ratings) is removed, since MBFC's data is not GPL and cannot be redistributed. `drush factcheck:sync-bias-ratings` now needs `--file` (a ratings file you are licensed to use) or `--fetch` (live from the MBFC API); the old 10-row sample, also MBFC ratings, is replaced by `data/bias-ratings-example.json` with invented rows showing the format. The Reuters entry in the `factcheck_trusted_sites_seeds` recipe no longer quotes MBFC's rating. Trusted sites already imported are untouched.
- **Terms submodule** (`ai_provider_universal_terms`, experimental): reads terms of service or a privacy policy, pasted or by URL, and returns findings in 19 categories, each quoting the clause it comes from; invented quotes are dropped. `POST /api/terms/analyze?_format=json` behind `use terms analyzer` (restrict access); JSON bodies only, and cookie sessions must send `X-CSRF-Token`; at most `requests_per_hour` (default 30) per user or IP, 429 above it (run `drush updb` on existing installs). Settings at `/admin/config/ai/terms`. Measured on Spanish documents only so far. See [docs/terms.md](docs/terms.md).
- Code review follow-ups: the claim cell in the content scan results is a `#plain_text` render array; the terms controller injects the config factory and current user instead of reaching the container.
- Docs: the content scan needs node **view** access (the docs and permission description said update; the code has required view since July).

## 1.0.0-beta4 — 2026-10-07

- **OpenAI Decisions backend** (`openai_decisions`, gpt-6-luna): the same typed decisions as `typesafe`, translated from OpenAI's wire format (`input`, `predicate`, named question arrays), so the Decision operation, `decide()`, text classification, fact check, the router's classifier and route failover work with Luna unchanged. Each backend now declares its probability rounding (System One: four decimals; OpenAI: undocumented, AI core's tolerance). An exhausted quota answered with HTTP 429 maps to `AiQuotaException`. Not verified against the live API.
- **SSRF guard on every redirect hop**: the standalone fact check checked only the URL typed in, so a public URL redirecting to a private or link-local address was fetched anyway. URL fetching moved into a reusable `PageFetcher` service.
- **Docs: decision models judge the state, not the world** — `noul` is the probability a statement is true *of the state passed*; on a bare statement they score near random.
- **The server form no longer wipes the host of a self-hosted decision server**: backends with a default endpoint hid host and port and cleared them on save, so editing a Laya server (backend `typesafe`) in the UI silently sent its calls to api.typesafe.ai. Backends whose default can be overridden (TypeSafe, OpenRouter, Hugging Face, Fireworks, Anthropic, Ollama Cloud) now show host and port as optional fields; fixed endpoints (Groq, Grok, DeepSeek) keep hiding them.
- **DeepSeek's current billing schedule**: peak is now 01:00-04:00 and 06:00-10:00 UTC on weekdays; weekends and Chinese public holidays are off-peak all day, at half price for every model. The old 16:30-00:30 UTC window had the router treating most peak hours as off-peak and vice versa. Price table updated to `deepseek-flash` and `deepseek-v4-pro` (checked 2026-10-01); existing model entities keep their stored costs. The current state comes from [SeekPeak](https://seekpeak.dev)'s status API (`api.seekpeak.dev/v1/status`, by SteffenR), cached until its next transition — a handful of requests a day — with the schedule and a built-in 2026 holiday list as fallback when it does not answer. `$settings['ai_provider_universal_deepseek_status_url']` points at another service with the same answer; `''` disables it. Price table ids also match versioned names such as `deepseek-v4.1-flash`.
- **AI core's Decision operation** (AI 1.6+, experimental): new `ai_provider_universal_decision` submodule. System One models (Jev, Laya, any `typesafe` server) answer typed noul/choice/score questions through `decision()`, so AI core's guardrails, automators and the Decision explorer reach them. Each model declares its capabilities: Laya does not declare noul criteria (they narrow its scores), so a question set using them fails before the request instead of scoring differently; image files are not declared yet. A structured (array) state is sent to the model as JSON. Smart routes can serve the `decision` operation, with the same one-retry failover as chat. Calls ride the chat bridge, so the pre-call gate, usage limits and usage recording apply. Existing System One models need a re-discovery (`drush aipdm`) to show up under the operation. Verified live against Laya on AI 1.6.x-dev (e454dfc).
- **Models are filtered by capability**: when AI core asks for models that can see images, call tools or return JSON (model selects, automators' vision check, `loadModelConfig()` flags), a model is hidden only when its catalog lists features without the one needed. Models without a catalog, and models whose operation types were ticked by hand, are always kept. Capabilities saved through AI core's model form (with `$settings['ai_override_models']`) win over both: AI core could not store them for our models before, because their ids contain a dot; they are now kept under an encoded key (`server__model`). Only `groq` and `anthropic` publish features today; Groq vision models are detected from their input modalities. Rationale and the alternatives discussed: [docs/model-capabilities.md](docs/model-capabilities.md).
- **`typesafe` backend** (TypeSafe Jev, native System One API): typed decisions — yes/no probability, choice, score — with calibrated confidence, exposed as chat. The conversation becomes the state; questions come from the model's extra request parameters (`questions:`) or a JSON system prompt; the answer text is the JSON `answers` object. Discovery reads `/v1/models` and prefills Jev's list input price (only for `jev*` ids). Also works with self-hosted servers speaking the same protocol — verified end to end against Laya behind a System One-compatible wrapper; not yet verified against the live TypeSafe API. A bridge until the `decision` operation type lands in AI core.
- **Decision models in smart routing and fact check**: the provider gains `isDecisionModel()` / `decide()`, a stable seam that moves to the `decision` operation type later. A decision model as the router's `classifier_model` is asked a typed small/large choice (Laya: 9/10 on hand-labelled prompts with `laya-typed-decisions`); as fact check checker it judges each claim against its evidence with a three-way choice, returning `CONTRADICTED` where MiniCheck cannot. Per-call questions now override a model's default `questions:`.
- **`text_classification` on decision models** (AI 1.4+): labels become one yes/no question each, sent in a single request and returned ranked by probability, so Jev and Laya are reachable from existing classifier consumers (Tagify AI, automators) without waiting for a decision operation type. The per-label question is overridable with `setConfiguration(['classification_question' => ...])`. The provider declares the operation without implementing AI core's interface, which ships only from 1.4, so AI 1.3 sites keep working.
- **A server that keeps failing is skipped for longer**: each failure in a row doubles its breaker mark (60s, 120s, 240s ... up to 16 minutes), and a quiet spell as long as the last mark resets the count. The mark lives in `cache.default`, so nothing is written while servers answer.
- **The call that hits a down server fails over too**: when a routed chat or `decide()` call fails in a way the breaker marks, the route is resolved again and the call retried once on the next candidate, so an outage no longer costs the first request. A failure the breaker ignores (a 400) is not retried.
- **Routing skips servers that just failed**: a call that fails with an unreachable host, a rate limit or an exhausted quota marks its server down for 60 seconds, and smart routing drops that server's models from the candidate pool meanwhile — a circuit breaker rather than a health check, so nothing extra is requested while everything works. Native backends also cap the connect timeout at 3 seconds. Measured with a route over [Laya, Gemma 3 4B]: first call 3.0s to fail (was 30s), the next ones answered by Gemma in ~1.3s, back on Laya once the mark expired.
- **Portable question sets across decision models**: `criteria` on a yes/no question is dropped (with a warning) when the target is Laya, which errors on the string form and narrows its scores on the form it accepts — measured here, the gap between urgent and calm messages fell from 0.81 to 0.63. Jev keeps the field. `choice` and `score` criteria are never touched.
- **`decide()` works with any model**: a decision is a shape of question, not a capability. A decision model answers natively; every other model is prompted for the same answers as JSON and normalized into the same shape (without invented confidence). Verified live on Laya and on Gemma 3 4B through Ollama. Smart routes can therefore hold Jev and a chat model as candidates for the same job, and fail over between them; `text_classification` works on both.

## 1.0.0-beta3 — 2026-08-26

- **Native (non-OpenAI) inference**: backends can now own chat execution through the opt-in `AiInferenceBackendInterface`, so a service that does not speak the OpenAI REST protocol works end to end instead of only appearing in the catalog. Opt-in and additive — backends that do not implement it, including ones contributed by other modules, are dispatched exactly as before. The pre-call gate, per-server usage limits, usage recording, smart routing, fact check and governance stay shared by both paths.
- **`anthropic` backend** (native Messages API): system-prompt hoisting, multi-turn content blocks, tool calling both ways, vision and PDF input, structured output emulated with a forced tool, extended thinking driven by the model's reasoning effort, SSE streaming and cache-aware token accounting. Per-model extra request parameters are forwarded verbatim, so prompt caching, server-side tools and `service_tier` are reachable from the UI. Discovery reads the paginated `/v1/models` catalog and prefills price, context and catalog features per Claude generation. Mapping is covered by kernel tests with mocked HTTP; not yet verified against the live API.
- **Non-chat operations on a native backend are refused with an explanation** (`AiMissingFeatureException`) instead of being sent over the OpenAI protocol to a server that does not speak it — previously a confusing 404 from a non-existent endpoint.
- **Provider-native request parameters**: new per-model **Extra request parameters (YAML)** field, merged verbatim into every chat request. Reaches parameters the module does not model itself — most usefully a provider's built-in tools (OpenAI `tools: [{type: web_search}]`) — with no code in the calling module. Documented presets in `definitions/extra_params.yml` (OpenAI web search, OpenRouter web plugin, xAI Live Search). `model`, `messages`, `stream` and `stream_options` are stripped. See [#3613029](https://www.drupal.org/project/ai_provider_openai/issues/3613029).
- **`deepseek` backend**: OpenAI-compatible at a fixed endpoint, with list prices, context and quality tier prefilled per model.
- **Time-of-day pricing in smart routing**: backends can expose a price multiplier (`getPriceMultiplier()`) that the router applies when comparing costs. DeepSeek uses it for its peak/off-peak schedule (list price 00:30-16:30 UTC, flat per-model discount outside that window), so a DeepSeek model competes on its discounted cost during off-peak hours and on list price during peak hours, with no configuration and no cron. Stored costs stay at list price and remain editable.
- **Negative model prices no longer block the server form**: OpenRouter reports `pricing: "-1"` for dynamic-priced models (`openrouter/auto`), which was stored as -1000000 USD/1M tokens and made the server form impossible to save (cost fields have a 0 minimum), so no model setting could be saved at all. Such sentinels are now treated as unknown cost. Update 10103 clears already-stored negative costs — run `drush updb`. Fixes [#3618874](https://www.drupal.org/project/ai_provider_universal/issues/3618874).
- **Re-discovery no longer deletes hand-made model duplicates**: a second model entity for the same raw model (the supported way to run one model under two configurations) survives as long as the server still offers that model. Previously every re-discovery deleted it.

## 1.0.0-beta2 — 2026-07-15

- **Content governance (EU AI Act Art. 50)**: new `ai_provider_universal_governance` submodule — AI-origin provenance events, disclosure rendering (`<meta name="ai-origin">` + visible label), Guardrail plugins (disclosure suffix, origin marker, fact-check, AI-likelihood), default Guardrail set attach. Scheduled content review via factcheck scan profiles.
- **Recipes** (under `recipes/`, applied with core's recipe runner):
  - `ai_content_governance_starter` — one-shot Art. 50 setup: disclosure fields, governance + factcheck enabled, `editorial_light` scan profile.
  - `ai_content_disclosure` — AI-origin/disclosure/exemption fields on Article only.
  - `factcheck_trusted_sites` — trusted-site content type (domain + reputation) for fact-check web evidence.
  - `factcheck_trusted_sites_seeds` — optional example trusted-site nodes (unpublished).
- **No more drupal/ai patches**: model IDs now use a dot separator (`server.model`, routes `route.<id>`) and model selects are flat `model_id => label` maps, so AI core and `ai_search` resolve Universal models unpatched. Fixes [#3611069](https://www.drupal.org/project/ai_provider_universal/issues/3611069) ("Universal | Array" in the embeddings engine select). Update 10102 migrates existing model IDs and stored references — run `drush updb`.
