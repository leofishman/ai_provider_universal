AI Provider: Universal 1.0.0-beta3

Changes since 1.0.0-beta2.

Highlights

  • Native (non-OpenAI) inference. A backend can now own chat execution through the opt-in AiInferenceBackendInterface, so a service that does not speak the OpenAI REST protocol works end to end instead of only showing up in the catalog. Additive: backends that do not implement it — including ones contributed by other modules — are dispatched exactly as before, and the pre-call gate, per-server usage limits, usage recording, smart routing, fact check and governance stay shared by both paths.
  • Anthropic (Claude) backend, speaking the native Messages API: system-prompt hoisting, multi-turn content blocks, tool calling both ways, vision and PDF input, structured output (emulated with a forced tool), extended thinking driven by the model's reasoning effort, SSE streaming and cache-aware token accounting. Discovery reads the paginated /v1/models catalog and prefills price, context and features per Claude generation.
  • DeepSeek backend, OpenAI-compatible at a fixed endpoint (api.deepseek.com), with list prices, context length and quality tier prefilled for deepseek-chat and deepseek-reasoner.
  • Time-of-day pricing in smart routing. DeepSeek bills on a peak/off-peak schedule — list price 00:30–16:30 UTC, a flat per-model discount outside that window (currently 50% off deepseek-chat, 75% off deepseek-reasoner). The router now asks the backend for a price multiplier and applies it at decision time, so during off-peak hours a DeepSeek model competes on its discounted cost and can win a route it would lose at 10:00 UTC — and stops winning it when peak hours return, with no configuration and no cron. Stored costs stay at list price, so what you see (and can edit) on the model page never drifts. New backends express their own schedule by overriding getPriceMultiplier(); backends that do not are billed flat, as before.
  • Extra request parameters (YAML), per model. Merged verbatim into every chat request, so provider-native parameters the module does not model itself — most usefully a provider's built-in tools (OpenAI tools: [{type: web_search}], the OpenRouter web plugin, xAI Live Search) — are reachable from the UI with no code in the calling module. Presets ship in definitions/extra_params.yml; model, messages, stream and stream_options are stripped. See #3613029.

Fixes

  • The server form is savable again when a provider reports a negative price. OpenRouter sends pricing: "-1" for dynamic-priced models (openrouter/auto), which was stored as −1000000 USD/1M tokens; because the cost fields have a minimum of 0, the browser then blocked submission of the whole form and no model setting could be saved — including turning on embeddings. Such sentinels are now treated as unknown cost. Fixes #3618874.
  • Re-discovery no longer deletes hand-made model duplicates. A second model entity for the same raw model — the supported way to run one model under two configurations — now survives as long as the server still offers that model.
  • Non-chat operations on a native backend are refused with an explanation (AiMissingFeatureException) instead of being sent over the OpenAI protocol to a server that does not speak it, which surfaced as a confusing 404 from a non-existent endpoint.

Upgrading

  1. composer update drupal/ai_provider_universal
  2. drush updb — update 10103 clears already-stored negative costs. Sites that discovered OpenRouter models on beta2 need this before the server form will save.
  3. Optional: on a model page, check Cost per 1M tokens for anything that came back empty and fill it in if you route on cost.

Known limitations

  • The Anthropic mapping is covered by kernel tests with mocked HTTP but has not yet been verified against the live API.
  • DeepSeek list prices are hardcoded; verify them against DeepSeek's pricing page before routing on cost. Discovery never overwrites a cost you edited.

Requirements

  • Drupal 11.1+ / 12
  • AI ^1.3
  • Key

Install: composer require 'drupal/ai_provider_universal:^1.0@beta'
