AI Provider: Universal 1.0.0-beta4

Changes since 1.0.0-beta3.

Highlights

  • Decision models: TypeSafe Jev, Laya and anything speaking System One. New typesafe backend for the native System One API (/v1/systemone): typed questions about a state — noul (probability a statement is true), choice and score — answered with calibrated probabilities in a single pass, not generated text. It works with the hosted Jev API and with self-hosted servers speaking the same protocol, such as Laya (open source); list price is prefilled for jev* models only.
  • AI core's Decision operation (AI 1.6+, experimental). The new optional ai_provider_universal_decision submodule implements the decision operation that landed in AI 1.6.0-dev, so AI core's guardrails, automators and the Decision explorer reach Jev and Laya through this provider. Each model declares what it supports (question types, structured state, instructions and criteria) and requests are validated before they are sent; Laya does not declare criteria on yes/no questions because they shift its scores, so a question set that uses them fails loudly instead of answering differently. Calls go through the same path as chat, so the pre-call gate, usage limits and usage recording apply. AI 1.6 is still a dev release and the operation is still changing upstream: the submodule refuses to install on older AI.
  • Decisions on AI 1.3–1.5 too. Without the submodule, decision models are reachable as chat (questions in the model's extra request parameters or a JSON system prompt, JSON answers back) and as text_classification (AI 1.4+: one yes/no question per label, ranked by probability), so Tagify AI and classifier automators can use Jev or Laya today. decide() asks any model typed questions: decision models answer natively, chat models are prompted for the same JSON, so a smart route can hold both.
  • Decision models in smart routing and fact check. A decision model can be the router's complexity classifier (Laya: 9/10 on hand-labelled prompts) or the fact check checker, where a three-way choice can return CONTRADICTED, which MiniCheck cannot.
  • Routing around failing servers. A call that fails with an unreachable host, a rate limit or an exhausted quota marks its server down, smart routing skips that server's models meanwhile, and the failed call itself is retried once on the route's next candidate. Marks double for a server that keeps failing (60 s up to 16 min) and reset after a quiet spell. Native backends cap the connect timeout at 3 s. Measured on a route over [Laya, Gemma 3 4B] with Laya down: the first call failed over in 3.0 s instead of 30 s.
  • Models are filtered by the capabilities AI core asks for (vision, tools, JSON output, structured output) in model selects, automators and loadModelConfig(). With $settings['ai_override_models'], settings saved through AI core's model form now stick for this provider's models, whose ids contain a dot that AI core's config could not store before. See docs/model-capabilities.md.

Fixes

  • DeepSeek's current billing schedule. Peak is now 01:00–04:00 and 06:00–10:00 UTC on weekdays; weekends and Chinese public holidays are off-peak all day, at half price for every model. The old 16:30–00:30 UTC window made the router rank DeepSeek at the wrong price for most of the day. The price table moves to deepseek-flash and deepseek-v4-pro. Holidays come from a built-in 2026 list; $settings['ai_provider_universal_deepseek_holidays_url'] can point at a JSON list of Beijing dates (["2026-10-01", …] or {"holidays": […]}), fetched at most once a day, with the built-in list as fallback.

Upgrading

  1. composer update drupal/ai_provider_universal
  2. drush updb (no new update hooks in this release; harmless).
  3. DeepSeek servers: run drush aipdm to discover the current models. Entities for deepseek-chat / deepseek-reasoner keep working but no longer get the off-peak discount in routing.
  4. To use the Decision operation on AI 1.6: drush en ai_provider_universal_decision, then drush aipdm so existing System One models are listed under it.

Known limitations

  • Jev has not been verified against the live TypeSafe API (signups were paused); everything decision-related is verified end to end against self-hosted Laya, and against Jev's documented wire format with mocked HTTP.
  • The Decision submodule targets AI 1.6.x-dev, whose interfaces may still change; it is excluded from drupal.org CI's static analysis until AI 1.6 is stable. Image files in decisions are not supported yet.
  • The built-in Chinese holiday list covers 2026 only.

Requirements

  • Drupal 11.1+ / 12
  • AI ^1.3 (the Decision submodule needs 1.6+)
  • Key

Install: composer require 'drupal/ai_provider_universal:^1.0@beta'
